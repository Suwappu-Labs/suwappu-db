## B1 — Workspace lints alignment

**Verdict:** ✅ Already met.

`Cargo.toml` declares:

```toml
[workspace.lints.rust]
unsafe_code = "forbid"

[workspace.lints.clippy]
all = { level = "deny", priority = -1 }
pedantic = { level = "warn", priority = -1 }
module_name_repetitions = "allow"
```

Every workspace crate inherits via `[lints] workspace = true`.
No `unsafe { }` block exists in `crates/**/src/**.rs`; the workspace
lint catches any future regression at compile time.

The gsx-dag side of B1 (mirroring this declaration into
`GlobalSettlementNetwork/gsx-dag/Cargo.toml`) is tracked separately
in that repo.

## B3 — CI security gates

**Verdict:** ✅ Met. Landed on `hardening/b3-ci-security-gates`.

`.github/workflows/security.yml` adds three jobs on PR + push + a
nightly cron:

- **clippy-strict**: `cargo clippy --workspace --all-targets -- -D
  warnings`. Promotes workspace `clippy::all = deny` warnings into
  CI fails.
- **cargo-audit**: `cargo audit --deny warnings` against fresh
  RustSec DB. Belt-and-braces alongside cargo-deny's `[advisories]`
  check (deny.toml).
- **secret-scan**: gitleaks-action with `fetch-depth: 0` so every
  commit's history is scanned.

`.cargo/audit.toml` mirrors `deny.toml`'s `[advisories.ignore]` (4
maintenance-only flags from transitive crypto deps:
RUSTSEC-2025-0134, 2024-0436, 2024-0388, 2025-0057).

## B4 — Consensus-time clock audit

**Verdict:** ⚠ Accepted — no consensus-time exposure in gsx-db.

gsx-db has no consensus path of its own (consensus runs in gsx-dag,
where `gsx-node/events.rs:104 SystemTime::now()` is the known issue
the broader plan tracks). The gsx-db audit catalogues every
`SystemTime::now()` / `Instant::now()` site and confirms none of
them sit on a determinism-load-bearing path.

### Sites audited (production, excludes `#[cfg(test)]`)

| Site | Surface | Risk |
|---|---|---|
| `crates/gsxdb-state/src/metrics.rs:164` `Timer::start` | Observability | None — output never crosses replicas |
| `crates/gsxdb-state/src/snapshot.rs:38` `StateSnapshot::new` (writes `timestamp`) | Snapshot metadata | None — field is informational; snapshot equality is over `state_root` + `encoded_state`, not timestamp |
| `crates/gsxdb-state/src/snapshot.rs:66` `StateSnapshot::is_valid` (freshness gate) | Operational filter | ⚠ Local clock skew can reject otherwise-valid snapshots. Caller-tunable via `max_age_secs`; not a soundness issue. Doc note added inline. |
| `crates/gsxdb-bridge/src/telemetry.rs:23,48,73` `BlockTimer` / `AnchorTimer` / `ParityTimer` | Observability | None |

### Recommendations

1. **No code change needed for gsx-db's consensus surface** — the
   sites identified are observability or local-only.
2. **Cross-replica determinism** (block MACs, anchor hashes, state
   trees) does NOT pull `SystemTime` / `Instant`. Verified by
   inspection of `Anchor::new` / `Anchor::hash` / `commit_node`.
3. Doc note on `StateSnapshot::is_valid` flags the local-skew
   sensitivity for operators tuning `max_age_secs`.

The gsx-dag side of B4 (named issue in `gsx-node/events.rs:104` plus
broader clock-skew injection) is tracked in that repo.

## B5 — Key custody enforcement model

**Verdict:** ✅ Met (documentation clarification, no code change).

`docs/spec/key-custody.md` already specified the HSM-only profile as
binding. B5 adds an explicit **Enforcement model** section that
clarifies the layered responsibility:

- **Build:** no compile-time gate against `InsecureSoftKey` (test
  binaries + local-dev need the soft-key path).
- **Deploy:** Terraform / Helm / AMI tooling pins `KEY_SOURCE` env
  and excludes raw-key filesystem paths.
- **Runtime:** the attestation-handshake check in the failure-modes
  table rejects peers without an accepted `module_type` and refuses
  to start without a valid local attestation.
- **Audit:** the validator's attestation is mirrored to the
  on-chain anchor / governance log for off-chain forensic verify.

The rationale for **operational over code-level** is recorded
inline:

1. A compile-time gate adds ~½ sprint of cross-crate feature
   plumbing for something the runtime handshake already rejects
   *more strongly* — the runtime gate catches keys from any
   loader, not just the `InsecureSoftKey` path.
2. The attack surface that matters is the binary that actually
   ships to production rollout; that surface is bounded by
   deployment tooling, not by Cargo features.

Cross-references added: `docs/architecture/deployment-topology.md`
(deployment-layer specifics) and this ledger.

## C2 — Versioning + release process

**Verdict:** ✅ Met. Landed on `external-dev/c2-release-process`.

### Workspace version bump

`Cargo.toml [workspace.package]`: `version = "0.0.1"` → `"0.1.0-pre"`.
The `-pre` suffix marks Phase-1 launch readiness; the first stable
tag will be `v1.0.0` once the gsxdb-types surface (C5) freezes.
Pre-1.0 minor bumps may include breaking changes per
`INTEGRATORS.md` "Stability promises".

### Release workflow

`.github/workflows/release.yml` (new) — triggers on `v*` tag push
(or manual `workflow_dispatch` for testing). Three parallel jobs:

1. **cargo-binary** (matrix: `x86_64-unknown-linux-gnu` +
   `aarch64-apple-darwin`) — `cargo build --release -p gsxdb-server`;
   uploads the binary + SHA-256 manifest as a workflow artefact.
2. **solidity-abi** — `forge build` + stages the committed
   `contracts/abi/{ILTPAnchorRegistry,LTPAnchorRegistry}.abi.json`
   for the release bundle.
3. **draft-release** — depends on both build jobs; extracts the
   matching `## [VERSION]` section from `CHANGELOG.md` via awk
   (falls back to `## [Unreleased]` if the version section is
   absent) and posts a **draft** GitHub Release with the
   artefacts. Draft, not publish — human review verifies the tag,
   changelog section, and artefacts before clicking publish.

### CHANGELOG

`CHANGELOG.md` gains a `## [0.1.0-pre] — 2026-05-16` section
summarising Pass A / Pass B / Pass C deliverables. The previous
substrate-work entries are moved under a
`## [Pre-Pass-A entries below]` header to keep history intact and
give the release-extraction awk a clean section boundary.

### Release flow

```sh
git tag -a v0.1.0-pre -m "Phase-1 launch-readiness pre-release"
git push origin v0.1.0-pre
# CI builds artefacts + drafts release; operator publishes after
# eyeballing the draft body + checksums on GitHub.
```

## C5 — Frozen type surface (gsxdb-types crate)

**Verdict:** ✅ Met. Landed on `external-dev/c5-gsxdb-types`.

### Approach

The plan's "extract into a separately-versioned crate" call was
implemented as a **re-export facade** rather than a physical type
move. Reasons:

1. **Surface stability.** Physical relocation forces type-paths to
   change across `gsxdb-state` + `gsxdb-bridge` + every test file
   (hundreds of imports). A facade re-export pins the same trait
   resolution while letting downstream consumers depend on a single
   stable crate.
2. **Independent versioning preserved.** `gsxdb-types` carries its
   own `version = "0.1.0-pre"` in Cargo.toml. Bumps here are
   decoupled from internal-crate bumps; downstream lockfiles
   surface gsxdb-types changes explicitly.
3. **Future migration path.** If a physical relocation is needed
   later (e.g. to publish gsxdb-types to crates.io while internals
   stay git-only), the facade is the surface that already maps
   one-to-one with the eventual moved types.

### New crate

`crates/gsxdb-types/`:

- `Cargo.toml` — `version = "0.1.0-pre"`; deps `gsxdb-state` +
  `gsxdb-bridge` via workspace paths.
- `src/lib.rs` — `#![deny(missing_docs)]` re-export facade. Three
  sub-modules (`tree`, `snapshot`, `dag`, `metrics`) carry the
  scoped surfaces; flat re-exports cover the headline types.
- `AuthScheme` re-exported directly from `gsxdb_bridge::anchor::types`
  with a docstring pinning the wire-encoding discriminant table.
- Stability contract documented in the crate-level rustdoc:
  `#[non_exhaustive]` additions are non-breaking; field
  removal/rename is a major bump.
- 1 smoke test (`frozen_surface_smoke`) constructs one of each
  major shape to catch re-export breakage at compile time.

### What's re-exported

- **State**: `Address`, `Balance`, `BalanceSlot`, `Commitment`,
  `State`, `StateChange`, `BridgeToken`, plus the dual-projection
  nonce / coin-value types.
- **Tree** (`tree::`): `StateTree`, `Node`, `Proof`, `ProofStep`,
  `Blake3Scheme`, `CommitmentScheme`.
- **Snapshot** (`snapshot::`): `StateSnapshot`, `SnapshotManager`.
- **DAG** (`dag::`): `DagBlock`, `DagStore`, `BlockHash`.
- **Metrics** (`metrics::`): `Metrics`, `Gauge`, `Histogram`,
  `Counter`, `Timer`.
- **Anchor**: `Anchor`, `AnchorHash`, `AnchorLog`, `AnchorDispatcher`,
  `ParityResult`, `AppendError`, `ChainId`, `GENESIS_PARENT`,
  `AuthScheme`, `EthAddress`, `AnchorAuthCredential`,
  `ExpectedVerifier`, `CredentialVerifyError`, `EcdsaVerifyError`,
  `verify_credential`, `verify_ecdsa`, `eth_signed_message_hash`,
  `Sp1PublicValues`, `ECDSA_SIG_LEN`, plus the L1 reader trait
  surface.

The S11.1-S11.3 additions (`VerifierConfig`, `EcdsaSecp256k1Signer`,
`AnchorSigner`, `SignerError`, `AnchorEntry`) pick up automatically
once those branches merge — the facade is already prepared to
re-export them.

What's NOT re-exported (volatile, depend on internal crate
directly if needed): `MoveExecutor`, `BlockStore`, `BlockExecutor`,
`Intent`, `Bundle*`, anything `#[doc(hidden)]`.

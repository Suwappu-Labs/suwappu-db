## C1 — License harmonization

**Verdict:** ✅ Met.

### gsx-db side

- `Cargo.toml` already declares `license = "Apache-2.0"` at the
  workspace level; every crate inherits via
  `[package] license.workspace = true`.
- `LICENSE` file added at repo root (canonical Apache-2.0 text +
  copyright line).
- `NOTICE` file added at repo root. Lists the three third-party
  components vendored via git dep with their own licenses:
  - `aptos-core` (Apache-2.0) — Move VM runtime + bytecode verifier
  - `aptos-labs/bcs` (Apache-2.0) — transitive via aptos-core
  - `crate-crypto/rust-verkle` (MIT) — banderwagon + IPA multipoint
- The MIT-licensed banderwagon / ipa-multipoint inclusion does not
  modify gsx-db's Apache-2.0 terms; MIT is permissive-compatible
  for redistribution under Apache-2.0 alongside the original MIT
  notice.

### Cross-repo posture

Per the locked decisions in `~/.claude/plans/research-how-to-serene-lark.md`:

| Repo | License | Status |
|---|---|---|
| `gsx-db` (this repo) | Apache-2.0 | ✅ documented |
| `gsx-dag` | Apache-2.0 | unchanged (out of scope here; mirror this LICENSE/NOTICE pattern in that repo) |
| `gsx-lattice-protocol` | Elastic License 2.0 | unchanged (intentional — non-commercial-redistribution profile) |

The license mismatch with `gsx-lattice-protocol` is intentional and
documented in the upcoming `INTEGRATORS.md` (C3). Downstream Rust
consumers wiring all three repos must consult `gsx-lattice-protocol`'s
Elastic 2.0 terms separately — its non-commercial-redistribution
clause prevents the simple "depend on it via crates.io" pattern that
Apache-2.0 allows.

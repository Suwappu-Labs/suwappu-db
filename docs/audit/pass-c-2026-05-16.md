## C2 — Versioning + release process

**Verdict:** ✅ Met. Landed on `external-dev/c2-release-process`.

### Workspace version bump

`Cargo.toml [workspace.package]`: `version = "0.0.1"` → `"0.1.0-pre"`.
The `-pre` suffix marks Phase-1 launch readiness; the first stable
tag will be `v1.0.0` once the gsxdb-types surface (C5) freezes.
Pre-1.0 minor bumps may include breaking changes per
`INTEGRATORS.md` "Stability promises".

### Release workflow

`.github/workflows/release.yml` (new) — triggers on `v*` tag push
(or manual `workflow_dispatch` for testing). Three parallel jobs:

1. **cargo-binary** (matrix: `x86_64-unknown-linux-gnu` +
   `aarch64-apple-darwin`) — `cargo build --release -p gsxdb-server`;
   uploads the binary + SHA-256 manifest as a workflow artefact.
2. **solidity-abi** — `forge build` + stages the committed
   `contracts/abi/{ILTPAnchorRegistry,LTPAnchorRegistry}.abi.json`
   for the release bundle.
3. **draft-release** — depends on both build jobs; extracts the
   matching `## [VERSION]` section from `CHANGELOG.md` via awk
   (falls back to `## [Unreleased]` if the version section is
   absent) and posts a **draft** GitHub Release with the
   artefacts. Draft, not publish — human review verifies the tag,
   changelog section, and artefacts before clicking publish.

### CHANGELOG

`CHANGELOG.md` gains a `## [0.1.0-pre] — 2026-05-16` section
summarising Pass A / Pass B / Pass C deliverables. The previous
substrate-work entries are moved under a
`## [Pre-Pass-A entries below]` header to keep history intact and
give the release-extraction awk a clean section boundary.

### Release flow

```sh
git tag -a v0.1.0-pre -m "Phase-1 launch-readiness pre-release"
git push origin v0.1.0-pre
# CI builds artefacts + drafts release; operator publishes after
# eyeballing the draft body + checksums on GitHub.
```

**Exit gate:** Dual-projection invariant property test passes on `BalanceSlot`. Five RocksDB CFs (`state`, `aggregates`, `evm_storage`, `evm_nonces`, `move_resources`) materialize at startup.

## Plan

S2 broken into three slices:

1. **`BalanceSlot` + property test** — type with EVM and Move projections; property test confirming projections always agree under arbitrary mutations. **No storage yet.**
2. **`BalanceStore` trait + in-memory impl** — abstract storage interface so the property test can run without RocksDB; in-memory impl for tests.
3. **RocksDB backend with 5 CFs** — real persistence; CF migration on startup; same property test runs against this backend.

## Completed

- [x] Slice 1: `BalanceSlot` type with EVM and Move projections in
  `crates/gsxdb-state/src/balance_slot.rs`. `proptest` dev-dep added.
  - 4 unit tests, 3 property tests
  - **Exit-gate test (type-level):** `projections_always_agree` — 10k cases in release pass in 0.19s

- [x] Slice 2: `BalanceStore` trait + `InMemoryBalanceStore` impl in
  `crates/gsxdb-state/src/store.rs`.
  - 4 unit tests (empty default, round-trip, replace, address independence)
  - 3 property tests over the trait surface, using a small address space (8 distinct addrs) to force key collisions:
    - `store_preserves_dual_projection` — every touched address always projects equal EVM/Move/canonical
    - `untouched_addresses_read_default` — addresses outside the op log read zero regardless of other ops
    - `op_replay_is_deterministic` — same op sequence on two empty stores produces equivalent state
  - **Exit-gate test (storage-level):** `store_preserves_dual_projection` — 10k cases in release pass in 0.70s

- [x] Slice 3: redb-backed `RedbBalanceStore` with 5 tables. See IQ-1
  (`docs/iq/IQ-1-redb-vs-rocksdb.md`) for the dev/prod backend split — local
  RocksDB build hit ENOSPC twice on a near-full disk; switched to redb for
  dev/CI, RocksDB returns in S8 behind `production-storage` feature.
  - 6 unit tests (open with 5 tables, default, round-trip, persistence across reopen, address independence, extreme values)
  - 2 property tests (`redb_preserves_dual_projection`, `redb_matches_in_memory`)
  - **Exit-gate test (persistent):** `redb_preserves_dual_projection` —
    1000 cases in release pass in 118s (each case opens a fresh DB).
